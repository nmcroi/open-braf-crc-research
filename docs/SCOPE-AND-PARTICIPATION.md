# Research scope and ways to participate

## Starting point and expansion

We start with colorectal cancer, particularly BRAF V600E/MSS, so that work has a concrete context. BRAF and BRCA are different names; this project's starting profile is BRAF.

The scope includes these research questions, without presupposing an answer:

- Treatment and resistance: what is supported for a precisely defined prior-treatment setting?
- Surgery and other local treatments: how do studies define selection, resectability and oligoprogression, and what outcomes and selection biases do they report?
- Immunotherapy and cancer-cell recognition: which findings concern which population, compartment and experimental model?
- Mechanisms across cancers: does a recurring pattern survive differences in tissue, genotype, treatment, assay and cohort?
- Data and methods: are identifiers, patient counts, measurements and analyses reproducible?

A question does not need to be BRAF-specific to belong here. Broader questions must state their own scope and evidence needs. A mechanistic connection to another cancer is a reason to investigate, not proof that a treatment transfers. Topic breadth must not erase population-specific distinctions. Propose new questions in an Issue before launching a large duplicate search.

## Who can help

| Group | Example contribution | Route |
|---|---|---|
| GitHub users with spare AI capacity | Verify five source identifiers or examine one bounded question using their own subscription | Claim an Issue, return sources and actual checks |
| Technically interested relatives or friends of other patients | Bring a well-defined research question, check a paper, organize source metadata | Issue or Discussion, no personal medical records |
| Programmers and data analysts | Reproduce a count, test an analysis or improve tooling | Fork and pull request |
| Researchers, clinicians and methodologists | Critique study selection, transferability, statistics or a proposed experiment | Evidence-linked review |
| People arriving through social media | Read the introduction, find a task matching their skills, or ask how to contribute | README and Discussions |

These are overlapping groups, not requirements to disclose a diagnosis or family relationship. The project is open beyond the organizer's own family.

## What contributing AI capacity means

You use your own existing tools, account and allowance for a task you choose. You decide how much time to spend. The project receives a reviewable result, not access to your account or a pool of tokens. Do not share API keys or account credentials. No new client program, paid API, always-on agent or automatic connection is needed.

For a normal chat: copy docs/TASK-PACKET.md, the selected Issue and approved public source links into your AI conversation. Return what was actually checked, citations, methods, limitations and counterevidence. A conversation transcript alone is not a research result. For code: use the reproducible contribution route in CONTRIBUTING.md.

Future automation is optional and would require separate design and explicit authorization. The current entry route already works with manual contributions. More models do not guarantee complete reading or discovery; measure corrected errors, reproducible findings and useful questions rather than message or token counts.
